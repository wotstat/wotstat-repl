# WotStat REPL

Десктопное приложение для разработки модов **World of Tanks** и **«Мир танков»**. Оно подключается к запущенному клиенту, выполняет Python 2.7-код в игровом потоке и показывает вывод в реальном времени.

![Окно приложения](./docs/img/hero.png)

## Возможности

- Поддержка и **World of Tanks** и **«Мир танков»**
- Выполнение Python-кода в живом клиенте.
- Потоковый вывод `stdout`, `stderr` и сообщений `BigWorld.log*` во встроенную консоль.
- Поиск по логам и фильтрация по уровню `log level`.
- Автодополнение по реальным объектам клиента с их сигнатурами.
- Запуск клиента/реплея или подключение к уже существующей запушенной игре.
- Автоматической поиск и запоминание добавленных клиентов.
- Встроенный MCP-сервер, чтобы управлять клиентом из ИИ-агентов.

## Установка

В [последнем релизе](https://github.com/wotstat/wotstat-repl/releases/latest)
публикуются приложения и игровой мод:

- Windows x64: портативный `wotstat-repl_<версия>.exe` и установщик
  `wotstat-repl_<версия>_win64-setup.exe`.
- macOS: универсальный образ `wotstat-repl_<версия>_macos.dmg` для Apple Silicon
  и Intel Mac.
- Linux x64: пакеты `wotstat-repl_<версия>_linux.AppImage` и
  `wotstat-repl_<версия>_linux.deb`.
- `wotstat.repl_<версия>.wotmod` для World of Tanks и
  `wotstat.repl_<версия>.mtmod` для «Мира танков». Оба файла содержат один и тот
  же универсальный игровой агент: подключение desktop-приложения по TCP и
  самостоятельный REPL в браузере.

Тот же универсальный агент встроен в каждую сборку приложения. Если приложению доступна
локальная установка игры, оно автоматически установит встроенную копию;
версионированный релизный файл нужен для ручной установки или игры на другой
машине. Версии для macOS и Linux могут подключаться к удалённой игре или клиенту
под Proton, но не запускают Windows-исполняемый файл игры напрямую.

Внутри desktop-приложения ресурс называется `wotstat.repl.mod`, а в игру
устанавливается как `wotstat.repl_<версия>.wotmod` для World of Tanks или
`wotstat.repl_<версия>.mtmod` для «Мира танков». Перед установкой
приложение удаляет предыдущие сборки `wotstat.repl` из папки этой версии
игры, поэтому дубликаты модов не остаются.

## Использование

1. Запустите приложение. Оно найдёт типичные установки игры автоматически; если нужной нет в списке, нажмите **Browse…** и укажите корень клиента.
2. Выберите клиент и нажмите **Launch Game**. Для запуска реплея используйте стрелку рядом с этой кнопкой и выберите `.wotreplay` или `.mtreplay`.
3. Приложение установит агент в папку `mods/<версия>` выбранного клиента, запустит игру и дождётся статуса **Connected**. Если игра уже запущена и агент был установлен ранее, нажмите **Connect**.
4. Введите код в редакторе и нажмите `Ctrl/Cmd+Enter`: будет выполнен выделенный код, а если выделения нет — весь редактор. Результат и журналы появятся в консоли справа.

### Web-REPL без desktop-приложения

1. Установите `wotstat.repl_<версия>.wotmod` для World of Tanks или
   `wotstat.repl_<версия>.mtmod` для «Мира танков» в `mods/<версия>` клиента.
2. Запустите игру.
3. Откройте [http://127.0.0.1:8768/](http://127.0.0.1:8768/) в браузере на той же машине.

Интерфейс доступен, пока запущена игра. Страница в браузере предоставляет только
REPL, логи, диагностику и автодополнение: в ней нет запуска/завершения клиента,
настроек сети агента и управления MCP. Тот же мод одновременно сохраняет TCP-
подключение, поэтому рядом можно использовать desktop-приложение и его MCP-
сервер. HTTP-сервер слушает только `127.0.0.1`; доступ по LAN намеренно не
включён. Сам REPL выполняет произвольный Python 2.7-код внутри игры, поэтому
открывать его для недоверенных пользователей нельзя.

## Сеть игрового агента

Универсальный игровой агент подключается к desktop-приложению по постоянному TCP-соединению.
Аутентификация токеном включена по умолчанию. Локальный режим слушает только
`127.0.0.1:8766`. Агент переподключается автоматически и хранит в памяти до
8 МиБ неподтверждённого вывода. Поэтому игру и UI можно запускать в любом
порядке: ранние логи будут доставлены, когда UI появится, пока игра продолжает
работать. Одна UI-сессия работает только с первым подключившимся агентом:
остальные игровые клиенты продолжают переподключаться и смогут занять сессию
только после выхода активного клиента.

Чтобы запустить игру и UI на разных машинах, откройте **Agent LAN** в строке
состояния и включите **Accept LAN connections**. Оставьте включённой галочку
**Secure connection** (это значение по умолчанию) и скопируйте конфигурацию в
`mods\configs\wotstat-repl\agent-network.json` относительно корня Windows-клиента.
Либо выключите **Secure connection**: агенты смогут подключаться анонимно,
даже если у них сохранён token от другого desktop. Без явного host агент находит UI по UDP
`8767`, после чего открывает исходящее
TCP-соединение на порт `8766` машины с UI. Это обычные непривилегированные
сокеты: права администратора не требуются, но firewall на машине с UI может
запросить разрешение на LAN-трафик. В insecure-режиме любой доступный из сети агент
сможет подключиться к REPL. В popover показываются все активные IPv4-
адреса listener’а, причём обычные частные LAN-адреса идут первыми. Если сеть блокирует broadcast, в конфиге
всё равно потребуется явно указать IPv4-адрес машины с UI. Детали формата
описаны в [протоколе агента](docs/AGENT_PROTOCOL.md).

Автодополнение строится непосредственно по подключённому клиенту. Игровой агент обходит живые объекты через `dir()`/`getattr()`, читает типизированные сигнатуры нативных функций из `__doc__` и использует runtime-интроспекцию для обычных Python-функций и связанных методов. Результаты хранятся в ограниченных короткоживущих кэшах, чтобы повторные запросы оставались быстрыми.

## MCP

При первом запуске приложение создаёт и по умолчанию включает локальный Streamable HTTP MCP-сервер. Он слушает `0.0.0.0:8765`; постоянный локальный адрес имеет вид:

```text
http://127.0.0.1:8765/mcp?token=<постоянный-UUID>
```

Токен и состояние сервера хранятся в `%LOCALAPPDATA%\WotStatWoTREPL\mcp.json`. Нажмите **MCP** в строке состояния, чтобы включить или выключить сервер, скопировать локальный либо сетевой URL, а также зарегистрировать `wot_repl` в ChatGPT Desktop/Codex или Claude Code. По умолчанию ChatGPT Desktop и Codex используют общий файл `%USERPROFILE%\.codex\config.toml` (либо `%CODEX_HOME%\config.toml`, если переменная настроена); приложение изменяет только `[mcp_servers.wot_repl]`. Пользовательские MCP-серверы Claude Code находятся в `%USERPROFILE%\.claude.json` (либо `%CLAUDE_CONFIG_DIR%\.claude.json`); приложение изменяет только `mcpServers.wot_repl`. CLI больше не требуется ни для одной из этих интеграций. Запись выполняется атомарно и сохраняет остальные настройки. После добавления или удаления перезапустите соответствующее агентское приложение.

Вручную добавить сервер в Codex можно так:

```sh
codex mcp add wot_repl --url "http://127.0.0.1:8765/mcp?token=<токен>"
```

Полный MCP-профиль Windows-приложения, запущенного на компьютере с игрой,
предоставляет девять инструментов:

| Инструмент         | Назначение                                                                                                    |
| ------------------ | ------------------------------------------------------------------------------------------------------------- |
| `wot_list_clients` | Показать установки World of Tanks на компьютере desktop-приложения вместе с доступными возможностями.       |
| `wot_start_client` | Установить/подключить и запустить локальный клиент, затем ждать главный поток, пока жив процесс; safety timeout задаётся только явно. |
| `wot_close_client` | Корректно закрыть активный локальный клиент; `timeout_ms` ограничен диапазоном 0–60000.                        |
| `wot_kill_client`  | Принудительно завершить активный локальный клиент после проверки процесса.                                    |
| `wot_exec`         | Выполнить Python 2.7-код в главном потоке игры; принимает `code` и необязательный `timeout_ms` от 1 до 30000. |
| `wot_read_log`     | Прочитать свежие сообщения лога; поддерживает `cursor`, `limit` и короткое ожидание через `wait_ms`.          |
| `wot_screenshot`   | Снять окно игры изнутри и вернуть стандартный MCP image content; поддерживает JPG/PNG и progress.             |
| `wot_mouse`        | Двигать виртуальный курсор игры, нажимать кнопки и крутить колесо, не перехватывая системную мышь.             |
| `wot_keyboard`     | Отправлять виртуальные key down/up/press напрямую во входной pipeline игры.                                   |

Удалённое desktop-приложение для macOS и других не-Windows сборок использует
отдельный намеренно сокращённый MCP-контракт. Он предоставляет только
`wot_exec`, выполняющий Python 2.7 в подключённом удалённом игровом агенте.
Поиск клиентов, start/close/kill, логи, скриншоты, мышь и клавиатура таким
MCP-сервером не рекламируются и через него не вызываются. В MCP-popover этот
режим явно помечен как **Remote REPL only** и предлагается запустить
Windows-приложение для полного набора инструментов.

Полное управление игрой через MCP намеренно требует, чтобы Windows-приложение и
World of Tanks работали на одном компьютере; сам MCP-клиент может подключаться к
приложению по сети. Поэтому `wot_list_clients` показывает только локальные
установки и их возможности `repl`, `input`, `screenshot`, `start`, `close` и
`kill`. Внутриигровой агент просит BigWorld создать временный скриншот с
уникальным именем, после чего Rust-приложение читает, проверяет и удаляет его
через общий локальный filesystem. Base64 используется только в финальном
стандартном MCP image content, как требует протокол. Публичный вызов отправляет
необязательные progress notifications и один финальный tool result. Используйте
`wot_close_client` прежде, чем прибегать к принудительному завершению.
